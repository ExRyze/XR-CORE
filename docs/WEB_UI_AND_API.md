# Web UI and API

## Frontend workflow

`local web/` contains the Vite source. `src/main.js` discovers widgets under `src/widgets/` and passes each element's `data-*` configuration to its mount function. `npm run build` generates static output under the firmware's `data/` directory. `data/` is mounted as LittleFS by the firmware.

Keep authored UI changes in `local web/`; generated bundles in `data/assets/` are production artifacts. Preserve `data/logo.raw` when rebuilding the UI because it is also used by the OLED.

Widget modules include value, value selector/input/dropdown, switch, stepper, status, percentage, chart, image, and push button widgets. The widget README in `local web/README.md` describes supported attributes and examples.

## Authentication

Login is performed using `POST /api/auth/login`. Successful login establishes a session cookie. Protected routes require that cookie. Mutating endpoints also validate the `X-Requested-With: XMLHttpRequest` header. Logout uses `POST /api/auth/logout`. Login credentials come from `WEB_AUTH_USERNAME` and `WEB_AUTH_PASSWORD` in `Config.cpp`.

## Endpoint inventory

The following routes are registered in `Web_Config.cpp`; authentication is required unless noted otherwise.

| Method | Path | Access | Purpose |
| --- | --- | --- | --- |
| `GET` | `/` | Public; page varies by session | Serves dashboard or login page. |
| `GET` | `/login`, `/login.html` | Public | Serves login page. |
| `GET` | `/api/device/public-status` | Public | Minimal device status. |
| `POST` | `/api/auth/login` | Public | Creates authenticated session. |
| `POST` | `/api/auth/logout` | Session | Ends session. |
| `GET` | `/api/system/status` | Session | System diagnostics. |
| `POST` | `/api/system/restart` | Session + request validation | Restarts device. |
| `GET` | `/api/device/status` | Session | Device status. |
| `GET` | `/api/wifi/status` | Session | Wi-Fi state. |
| `GET` | `/api/wifi/scan` | Session | Scanned network information. |
| `POST` | `/api/wifi/save` | Session + request validation | Saves station credentials. |
| `POST` | `/api/wifi/clear` | Session + request validation | Clears station credentials. |
| `POST` | `/api/wifi/ap-password/clear` | Session + request validation | Clears saved AP password state. |
| `GET` | `/api/mqtt/settings`, `/api/mqtt/status`, `/api/mqtt/ca/status` | Session | MQTT configuration and status. |
| `POST` | `/api/mqtt/settings`, `/api/mqtt/ca/upload` | Session + request validation | Saves MQTT settings or uploads CA certificate (maximum 8 KB). |
| `GET` | `/api/lora/settings`, `/api/lora/status` | Session | LoRa settings and status. |
| `POST` | `/api/lora/settings` | Session + request validation | Saves LoRa settings. |
| `GET` | `/api/dummy/telemetry` | Session | Returns generated demo telemetry. |
| `GET` | `/assets/*`, `/logo.png` | Public static files | Serves UI assets. |

This inventory reflects the current source and may change. Check `Web_Config.cpp` for exact request parameters, response shape, validation, and restart behavior before writing a client.

## Dummy telemetry

The dashboard demo endpoint returns a JSON object containing `value`, `unit`, and `updatedAt`. The value is generated by `DummyTelemetry`; it is not a physical sensor reading. UI widgets can poll it with `data-api-url="/api/dummy/telemetry"` and `data-value-path="value"`.

## HTTP and trust boundary

The firmware serves plain HTTP. Do not expose it directly to the internet or send credentials over an untrusted network. The public status endpoint and static login assets are deliberately unauthenticated; keep public status data minimal.
